# Start here — five-person team

There are exactly five people in this project: the team leader/developer, three developers, and one client/stakeholder.

## Choose your guide

- [Team leader/developer](team-leader.md)
- [Developer A — domain model and core logic](developer-a.md)
- [Developer B — interface and Kanban](developer-b.md)
- [Developer C — task features and tests](developer-c.md)
- [Client/stakeholder](client-guide.md)

## First group session

1. Introduce each person's role and confirm their GitHub username.
2. The client explains the real workflow and validates the problem statement.
3. Read the source dossier together, especially B-01 to B-07, FR-01 to FR-22, and UC-01 to UC-13.
4. Resolve or assign the open questions in the needs analysis.
5. Confirm Issue owners and reviewers.
6. Agree on a realistic weekly check-in time.
7. Record only decisions actually made in a dated meeting note.

## Ground rules

- The original PDF is the baseline; keep it unchanged.
- The client validates user needs and behavior, not code quality.
- Each developer owns real implementation and tests.
- Every PR is reviewed by another person.
- No one commits directly to `main` or `develop`.
- A task is not complete until its acceptance criteria are met, evidence exists, and the PR is merged.
